Recipe card pipeline

Rebuilds Obsidian recipe notes from FastFoto scans using macOS Vision OCR and USDA nutrition.

Originals in FastFoto/1980s_reciepes and FastFoto/1990s_reciepes are never modified. Upright copies go to FastFoto/rotated/{era}/ and are embedded in each note.

Duplex rotation (portrait FastFoto scans of landscape index cards): _a front = 90° clockwise, _b back = 270° clockwise (90° CCW / front + 180). Same long-edge flip as a typical ADF duplex scan. Pair/rotate/rebuild use this rule; do not reuse per-image OCR rotation for the display JPEGs.

Setup (macOS)

cd /Users/mattwatier/Repo/Recipe
python3 -m venv .venv
source .venv/bin/activate
pip install -r Scripts/requirements.txt
xcrun swiftc -O -o Scripts/bin/ocr_vision Scripts/ocr_vision.swift \
  -framework Vision -framework AppKit -framework Foundation

Put USDA_API_KEY= in Scripts/.env (gitignored). Never commit that file or paste the key into notes/README.

Human-in-the-loop (inbox → outbox)

Unprocessed notes live in Recipes/_Inbox/ as RAW OCR + source card images only (tiny YAML with kaper + card_id). Meal folders (Breakfast, Mains, Sides, Desserts, Drinks, Condiments) are for after processing. Mains have a major protein; Sides are vegetables, starches, and small-bite snacks.

  1. Edit the RAW OCR in _Inbox against the card photos.
  2. Move a note into Recipes/_Outbox/ when you want it turned into a recipe.
  3. Run:
python Scripts/process_outbox.py

The processor:

  • reads RAW OCR from the note (plain text or markdown; sidecar only if that section is missing; does not re-OCR)
  • reconstructs a full recipe (Scripts/reconstruct.py): # / ## / **Serves:** are headings/metadata; ingredients inside directions are pulled out only if that food is not already listed (loose name match; prefer the Ingredients-section entry; keep the richer amount); a verb line plus a following list is one step; all stated bake/simmer/sauté times are summed into duration ({n}m); steps with no time get a typical duration. Clock times stay out of the step note. Overnight is never invented unless the card says so. Kaper YAML has no markdown; step titles are short actions and notes are instruction sentences
  • writes a Kaper fenced block plus cooking frontmatter (type, course, era from card_id, servings, times, oven, allergens)
  • estimates calories and macros per serving via the USDA API
  • leaves RAW OCR and image embeds intact
  • renames the file to the card’s recipe title when OCR has a clear title
  • files the finished note into the matching meal folder. Mains have a major protein; Sides are vegetables, starches, and small-bite snacks. Breakfast, drinks, desserts, and condiments stay their own folders.

Empty outbox is a no-op. Idempotent: a second run with nothing in _Outbox does nothing.

Reconstruction contract

Leave RAW OCR untouched. Markdown # / ## / **Serves:** are headings, not ingredients. Pull ingredients out of instructions; reconstruct card shorthand. Only add a direction-derived ingredient if that food is not already in the ingredient list. Match loosely on the food name (ignore amount, unit, prep note, and minor OCR spelling). Prefer the Ingredients-section entry; if one mention is quantified and the other is not, keep the richer amount. Sum all stated step times into duration ({n}m); infer typical times when missing. Clock times do not stay in the step note. Overnight is never invented unless the card says so.

Kaper YAML cannot contain markdown. Strip **, #, _, backticks, and list markers from titles, notes, ingredient names, and tags. Leave markdown in ## RAW OCR.

Kaper steps: title is a short action, optionally numbered (1. Steam, 2. Poach, 3. Combine & Garnish). note is a full instruction sentence. Clock times go in duration only. Keep qualitative doneness in the note (until tender, till fragrant, reduce by half). Optional tip: for extras such as internal temperature. Do not repeat whole-ingredient amounts in the instruction (Steam broccoli, not Steam 2 heads of broccoli); keep amounts only when subdividing. Cooking tools (dutch oven, buttered pan, mixing bowl) stay in the instruction, never the ingredient list. Encoding: Scripts/parse.py, Scripts/reconstruct.py (shape_step), Scripts/notes.emit_kaper. Reshape existing notes with python Scripts/rebuild_from_ocr.py --cleanup-steps.

Kaper amount: is a whole number or decimal only — never a fraction. Unicode and ASCII fractions in RAW OCR (½ ¼ ¾ ⅓ ⅔ ⅛ 1/2 1/4 3/4, mixed 1½, fraction-slash 1⁄2) must become floats in YAML (amount: 0.5 or .5). The fraction glyph must not remain in name (including a leading ⁄2 after 1 was parsed separately).

Kaper unit: is not part of name. Size words, kitchen measures, and weights all count. Recognize OCR aliases, then canonicalize:

  • Size / count: small, medium, large, whole, clove, can, stick
  • Volume: cups / c. → cup; tsp / t. / t → tsp; Tb / T. / T / tbsp / tablespoon → tbsp; pint → pt; quart → qt; pinch, dash, pkg
  • Weight: lbs / lb / pounds / # → lb; grams / g / gms → g; oz / ounces → oz

A # after an amount is pounds (2# beef → unit: lb), not a markdown heading.

Kaper prep/knife directions belong in note, not in name. Match case-insensitively, including OCR near-misses. Canonical vocabulary: halve, quarter, wedge, chunk, rough chop, chop, fine chop, large dice, medium dice, small dice, mince, slice, thin slice, rings, strips, julienne, chiffonade, crush, smash, mince to a paste.

Example — OCR ½ small onion, peeled and chopped → amount: 0.5, unit: small, name: onion, note: peeled and chopped. Wrong: amount: 1, name: ⁄2 small onion. Example — OCR 2 cloves garlic, minced → amount: 2, unit: clove, name: garlic, note: minced. Amount/unit/note parsing lives in Scripts/parse.py (parse_amount, split_amount_unit_name, UNIT_ALIASES, _split_note).

Do not duplicate ingredients pulled from directions. If onion is already under Ingredients, do not add it again from "sauté the onion". Match loosely on food name (ignore amount/unit/prep and minor OCR spelling). Prefer the Ingredients-section entry; keep the richer amount if only one mention is quantified (Scripts/parse.py: food_names_match, dedupe_ingredients, add_new_ingredients).

First import (pair → rotate → OCR sidecars → notes → nutrition)

source .venv/bin/activate
python Scripts/pipeline.py --sample          # sanity cards first
python Scripts/pipeline.py --all             # every unique stem

OCR text is written once to Scripts/ocr_raw/{card_id}.txt with === FRONT === / === BACK === markers, and copied into a visible RAW OCR section on each note. Existing sidecars are not overwritten on import unless you pass --force-ocr. After that, the note wins.

After you clean up OCR (rebuild without moving folders)

  1. Edit the RAW OCR section in the recipe note (not the sidecar). Exact heading and format:
## RAW OCR

```
...card text...
```
  1. Rebuild the Kaper form + derived frontmatter from that text (keeps the current folder/filename):
python Scripts/rebuild_from_ocr.py
python Scripts/rebuild_from_ocr.py --card 1980s_reciepes_0002

Rebuild does not re-OCR unless you pass --reocr. It reads ## RAW OCR first (sidecar fallback if the section is missing), then:

  • replaces the kaper fenced block (including title)
  • updates derived frontmatter: servings, times, oven, nutrition, allergens, tags, course/cuisine
  • never overwrites the RAW OCR section
  • syncs Scripts/ocr_raw/{card_id}.txt from the note so the sidecar stays aligned
  • keeps the existing filename, kaper id, card_id, era, card_sides, status, and rotated image footer

Notes with status: reviewed are skipped (Kaper/frontmatter unchanged) unless you pass --force.

python Scripts/rebuild_from_ocr.py --all
python Scripts/rebuild_from_ocr.py --status ocr-draft
python Scripts/rebuild_from_ocr.py --migrate-ocr   # visible ## RAW OCR only; no Kaper rebuild

Optional OCR refresh (destructive to human sidecar edits only with --force-ocr):

python Scripts/rebuild_from_ocr.py --reocr                  # Vision OCR for missing cache; sidecars stay write-once
python Scripts/rebuild_from_ocr.py --reocr --force-ocr      # overwrite sidecars from new OCR; notes still win unless RAW OCR is missing
python Scripts/pipeline.py --all --skip-ocr                 # reuse sidecars + cache; still rotate if needed
python Scripts/pipeline.py --nutrition-only

Notes are keyed by card_id. Re-runs update existing files instead of duplicating them.
